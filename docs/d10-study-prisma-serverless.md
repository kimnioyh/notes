## 0. 핵심 개념 먼저 — 핫 리로드(Hot Reload / HMR)

- **렌더링 아님.** 렌더링 = 브라우저가 화면 그리는 것.
- 핫 리로드 = **dev 모드에서 파일을 저장할 때마다, 서버가 바뀐 코드 모듈을 재시작 없이 다시 평가·실행**하는 편의 기능.
- 즉 파일 저장 → 그 모듈(예: `prisma.ts`)이 **처음부터 다시 실행됨**.
- **production엔 없다.** 배포된 코드는 고정 → 모듈은 딱 한 번만 로드됨.

## Why 3 — 왜 SQLite → Neon(Postgres)인가?

**한 줄:**
> Vercel 서버리스는 (1) 요청 끝나면 서버가 꺼져 데이터가 날아가고(**휘발성/stateless**), (2) 요청마다 여러 인스턴스가 독립적으로 떠서 파일을 공유 못 한다(**비공유/분산**). 그래서 파일 기반 SQLite는 데이터가 사라지거나 조각난다 → **항상 떠 있고 모두가 네트워크로 붙는 공용 DB(Neon)** 가 필요.

**유도 사다리 (혼자 다시 밟아볼 것):**
1. 배포하면 내 코드는 어디서 도나? → **남의 서버(클라우드)**.
2. SQLite 데이터는 어디에? → **내 컴퓨터 프로젝트 폴더의 `.db` 파일**.
3. 남의 서버가 내 `.db` 파일을 볼 수 있나? → **못 봄** → 배포형 DB 필요.
4. "그럼 `.db`를 git에 같이 올리면?" → 안 됨:
   - 서버리스는 요청 끝나면 **꺼짐** → 그때 쓴 결제 내역 **날아감**(휘발성).
   - 요청마다 **여러 인스턴스**가 독립적으로 뜸 → A서버에 저장한 결제를 B서버는 모름(비공유).

**킬러 후속 대비:**
- Q. 왜 하필 Neon? 일반 Postgres 두고?
  → Neon = **서버리스 Postgres**. 서버리스 함수가 요청마다 확 늘었다 줄어드는 커넥션 패턴에 맞게 커넥션을 다룰 수 있음. (일반 RDS는 커넥션 수가 고정적이라 서버리스 폭증에 취약)

## Why 2 — 왜 싱글톤(globalThis 캐싱)인가?

```ts
const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };
export const prisma = globalForPrisma.prisma ?? new PrismaClient({ adapter });
if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
```

**한 줄:**
> dev에서 파일 저장할 때마다 핫 리로드가 `prisma.ts`를 다시 실행 → 매번 `new PrismaClient()` → PrismaClient가 계속 새로 생기고 각자 DB 커넥션을 열어놓음 → 쌓이다가 **커넥션 고갈(`too many connections`)로 터짐.** globalThis에 캐싱해두고 `?? new` 로 **이미 있으면 재사용** → 몇 번 저장하든 PrismaClient는 1개.

**유도 사다리:**
1. dev에서 파일 저장 → 핫 리로드가 `prisma.ts` **다시 실행**.
2. 그럼 `new PrismaClient()`도 매번 다시 실행 → 저장 30번 = **PrismaClient 30개**.
3. 각 PrismaClient가 DB 커넥션을 열어둠 → 쌓이면 **DB 최대 커넥션 초과 → 터짐**.
4. **왜 dev에서만?**(13번 줄) → production은 핫 리로드가 없어 모듈이 한 번만 로드됨 → PrismaClient도 한 번만 생김 → 캐싱 불필요.

## ★ 오늘 제일 중요한 것 — 두 "여러 개"를 구분하라

| | 문제 | 원인 | 해결 |
|---|---|---|---|
| **Why 3** | 배포 시 데이터 안 됨 | 서버리스 **여러 인스턴스**·휘발성 | 외부 공용 DB(Neon) |
| **Why 2** | dev에서 커넥션 터짐 | 핫 리로드가 **모듈 재실행** | globalThis 싱글톤 |

둘 다 "여러 개"가 나오지만 **층위가 완전히 다르다.**
- Why 3 = 배포 환경에서 **인스턴스(서버)가 여러 개**.
- Why 2 = dev 한 프로세스 안에서 **객체(PrismaClient)가 여러 개**.

구분해서 말하면 "진짜 이해했네", 합치면 바로 찔린다. (처음엔 나도 합쳤다 → 13번 줄 모순으로 분리해냄.)
